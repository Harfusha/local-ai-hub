# Local AI Hub installation prompt

Install Local AI Hub using the repository's supported installer for this operating system. Keep the user's existing configuration and merge the generated agent instructions into their existing agent files.

The normal installation must install the `token-economizer` companion skill and token-economy dependencies, create the `tokcount`, `trim-run`, and `repo-map` commands, and add the Hub virtual-environment scripts directory to the user's `PATH`. It also installs the `grep-ast` and `files-to-prompt` CLIs. After installation or schema regeneration, reload the MCP server or restart the agent host so it receives the updated `PATH`, action schemas, and descriptions.

Use these commands by default for bounded repository work: `tokcount`, `repo-map`, `grep-ast`, `files-to-prompt -c`, `ast-grep`/`sg`, `rg`, `fd`, and `jq`. Route repeatable tests and validation through `local_ai_command` when available. `trim-run` may wrap only commands accepted by the safe read/validation/build allowlist; for other output, pipe it into `trim-run` stdin mode. Use `repomix --stdout --compress` so it does not write an output file.

Keep command-broker defaults limited to safe reads, validation, and builds. Do not enable unrestricted commands, unknown executables, or mutation globally to make the tools work. Verify the install with `tools/doctor.py` and `hubctl status`.

Use installed `qwen2.5-coder:0.5b` only for background preprocessing, `qwen2.5-coder:1.5b` for quick tasks, `qwen2.5-coder:3b` for complex tasks, and `qwen2.5-coder:7b` for the hardest reasoning. On Intel-only GPU systems, optionally install llama.cpp's Windows/Linux SYCL build and route all four aliases through the loopback router; follow `docs/LLAMA_CPP_SYCL.md`. Keep `llama_cpp.mode = "auto"` and Ollama fallback enabled by default. NVIDIA/AMD discrete-GPU systems keep their existing Ollama CUDA/ROCm route; AMD iGPU does not use Intel SYCL. Keep simple deterministic repository tasks on indexed or deterministic Hub actions. Before removing Ollama, copy its GGUF model blobs and verify all four aliases through the llama.cpp router. Use only aliases confirmed by Ollama `/api/tags` or the router's `/models` endpoint.

After installation, derive the MCP action schemas and descriptions, `local-ai-orchestrator` skill and references, and managed agent instruction blocks from the effective feature configuration. Include every enabled action and its required arguments, plus trigger guidance for specialized task, RAG, command, code-intelligence, and operator-dashboard capabilities; omit disabled ones. In particular, expose `local_ai_work` only when `work_orchestrator` is enabled. When Agent OS is enabled, make its trigger and lifecycle explicit: use it for non-trivial multi-step, long-running, delegated, or acceptance-criteria work; create a task contract, checkpoint progress, compile context when needed, attach validation receipts, and gate completion with `verify_completion`.
