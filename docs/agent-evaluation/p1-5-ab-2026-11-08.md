# P1-5 Hub A/B evaluation — 2026-11-08

## Result

One matched synthetic coding task ran with and without Local AI Hub. Both arms finished with passing tests and no observed validation-quality regression. This single pair showed **higher** token use and elapsed time with Hub; it establishes no general performance or savings claim.

The Hub response total is the sum of each successful MCP response's `response_budget.returned_tokens`: preprocess 774; two searches 1,609 and 1,220; five source slices 438, 603, 540, 483 and 440. No identical MCP request was repeated. One later `src/fees.py` slice overlapped an earlier slice; its 440-token response envelope is included once in the total. MCP response estimates and Codex input usage are separate measurements and must not be added as if they were disjoint.

The signed observed Codex token deltas are +4,577 input and +354 output. Cached input is reported separately and is already included in input tokens. There is no baseline evidence ID for a Hub savings claim; this report claims no savings.

## Excluded calibration runs and limits

Earlier calibration runs used roots under Windows `Temp`. Hub correctly ignored these as ephemeral/system directories; their retrieval outcomes are excluded from the matched result. A first service-control attempt also exposed that `hubctl --config` does not route lifecycle actions: `tools/service.py` reads `LOCAL_AI_CONFIG`. The shared Hub was restored immediately. The accepted pair instead used a stable disposable project root, an explicitly isolated state directory, and `LOCAL_AI_CONFIG`.

This is one task and one run per arm. It does not measure repeated identical-query cache reuse, local-compute substitution, dollar cost, or general workload quality. Repeat with more tasks and repetitions before making broader latency or savings claims.
