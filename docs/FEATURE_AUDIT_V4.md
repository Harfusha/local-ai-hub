# Local AI Hub 4.0 deterministic feature audit

Audit target: branch `codex/v4.0-hardening`, current checkout, 2026-09-21.

Scope: `FEATURES.md`, `README.md`, current `docs/` documentation, MCP declarations and
routing in `src/local_ai_hub/mcp_server.py`, feature projection in
`src/local_ai_hub/features.py` and `src/local_ai_hub/generator.py`, packaged
defaults in `defaults.toml` and `src/local_ai_hub/defaults.toml`, and current
tests. Runtime/model output, queued output, stale output, and advisory model
review were not used as evidence.

Status labels mean: **covered** = deterministic source and test evidence;
**conditional** = source/test evidence exists but optional backend or runtime
proof is absent; **gap** = current deterministic mismatch or failing test;
**not proven** = no valid runtime/whole-suite evidence.

## v4 quality gates added in this audit

- Unified context is authoritative and task-scoped: `/api/agent-state/context` returns a complete `task_context` envelope even for agent-only tasks, and `local_ai_task(task_id=...)` consumes the same compiled context before model invocation.
- Local-model output is advisory only. Relevance, provenance, terminal state, schema and minimum-quality gates reject stale, queued, malformed or below-floor results before they can affect completion.
- Telemetry stores bounded metadata only and preserves existing SQLite history during additive schema migration; token accounting records context digest, replay and bounded efficiency metadata without prompts, source text, model output or absolute paths.
- Async execution has bounded admission, queue limits, cancellation/process cleanup and resource-pressure degradation/rejection. Context/response budgets are enforced after authoritative fields are attached.
