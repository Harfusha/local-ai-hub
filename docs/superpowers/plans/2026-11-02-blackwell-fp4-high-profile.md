# Blackwell FP4 and high-profile model plan

**Goal:** Evaluate and, only after capability and quality checks, prefer suitable FP4 inference for the RTX 5070 Ti while preserving working model roles and safe fallback.

**Architecture:** Retain Ollama and the existing provider contracts. Extend the existing llama.cpp adapter and managed runtime with a separately tested Windows CUDA route; select it per model and verified capability rather than globally switching every model. Keep preprocessing and embedding providers unchanged until independently evaluated.

## Proposed model roles

- Keep `qwen2.5-coder:1.5b` for configured preprocessing; `qwen2.5-coder:3b` for fast/background code; `qwen2.5-coder:7b` for heavier code; `qwen3.5:9b` for reasoning, general and vision. These are the source `high` defaults, not independently proven optimal choices.
- Evaluate `qwen3.5:4b-nvfp4` only as an optional fast advisory candidate against the current 3B route; the previously installed `qwen3.5:4b-q4_K_M` candidate is retired. Require a fresh installed-tag snapshot and measured quality before recommending the NVFP4 candidate. Evaluate the actual 9B and vision workloads separately before proposing replacements; no 9B FP4 result is established here.
- `qwen2.5-coder:14b` and `gemma4:12b` are retired from current recommendations by the 2026-11-06 model-pruning decision; historical inventory and evaluation evidence remains. Keep embedding and fallback models pending an inventory of all consumers and actual configured providers.

## Work packages and acceptance

1. **Repeatable evidence.** Pin upstream release and model revisions, verify hashes and quantization metadata; record driver, runtime, GPU offload, free VRAM, background load, context, batch, activation precision and model parameters. Repeat paired, alternating warm runs for 512 and 2048 input tokens and 128 generated tokens. Measure TTFT, longer contexts, memory and cold load separately. Profile or inspect runtime kernel selection before claiming native W4A4 execution. Compare the same source model and quantization recipes where available.
2. **Quality and functionality.** Run the existing local model evaluation suites on identical fixed cases for 4B FP4, 4B Q4_K_M and current fast model; include code, Czech, structured output, tool calls and model loading. Check vision with the correct projector separately. Set acceptance thresholds before comparing results. Do not enable direct edits or final verification based on these measurements.
3. **Runtime integration.** Review `src/local_ai_hub/llama_cpp.py`, `llama_cpp_runtime.py`, hardware detection, scheduler and model policy. Add a pinned CUDA build for the supported platform, verify download provenance and resource lifecycle, and test capability detection for SM 12.0, missing drivers, incompatible models, insufficient VRAM and failed server startup. Preserve existing SYCL behavior and Ollama fallback. Confirm streaming, cancellation, concurrency, generation settings, tool calling and vision work before admission.
4. **Routing.** Prefer a validated FP4 model only when the exact model, backend, GPU, driver, available VRAM and quality gate all pass. Honor explicit user overrides and model capabilities. Otherwise fall back to the existing role. Do not infer native acceleration from file suffix, card name or hardware capability alone. Keep one supervised runtime owner and GPU scheduling consistent.
5. **High-profile qualification.** Compare candidates under realistic Hub workloads and context sizes, including model-switch latency and concurrent preprocessing. Assign the 4B candidate only if it meets the quality gate and improves the chosen end-to-end metric. Benchmark and qualify 9B FP4 independently before changing its roles. Update `docs/MODEL_CAPABILITIES.md`, defaults, tests, `docs/INSTALL_PROMPT.md` and `docs/UPDATE_PROMPT.md` for any actual policy change.
6. **Cleanup plan.** Inventory actual model references across Hub, OpenCode, configured clients, preprocessing and embedding, including user-invoked models. Verify aliases and shared blob digests. Candidate duplicate tag: `qwen3.5:9b-q4_K_M` shares ID `56671c2ab938` with `qwen3.5:9b`; remove the former only after confirming no consumer uses that exact name. Removing one alias may free no space. Review `qwen2.5vl:3b`, `qwen2.5vl:7b`, `qwen2.5-coder:0.5b`, `qwen3-embedding:0.6b`, `qwen3.5:4b-q4_K_M`, `gemma4:12b` and `qwen2.5-coder:14b` individually; do not classify them as unused from a static profile alone. Remove only confirmed unreferenced models after replacement validation, with a recovery list and measured reclaimed disk space.
7. **Integration gate.** Run focused tests for detection, routing, fallback, lifecycle and configuration, then the repository release validation appropriate to the final diff. Exercise real Windows CUDA inference and existing Ollama flows; document tested runtime versions and limitations. Roll back routing if quality, reliability or memory criteria fail.
