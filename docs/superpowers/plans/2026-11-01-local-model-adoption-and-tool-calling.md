## Receipt publication and rollback race

The bounded work patch counter is process-local; the broker reads the Agent OS task checkpoint generation and immediately persists a verification receipt. Advancing the task generation only after a patch is unsafe if the process dies between file mutation and the advance. Advancing it immediately before rollback is also insufficient if a receipt can complete the task after validation but before rollback begins.

Before enabling post-mutation receipts, implement a durable, fenced protocol that invalidates prior task evidence before any mutation, prevents task completion while the work transaction remains rollback-capable, and publishes only broker-authenticated command evidence bound to the committed repository revision and the same task/root/owner/generation. Recovery must invalidate evidence before restoring files, remain correct across a crash at every boundary, and refuse ambiguous or conflicting ownership. Exercise concurrent task completion, a lost fence, command failure, post-validation rollback, repair, restart and external file changes in integration tests. Until these gates pass, the existing `not_recorded` result remains authoritative.


### Empty-journal recovery boundary

The current recovery scans only transient work-order states, while successful handoff becomes terminal before journal cleanup. A crash may also leave a task barrier after its journal is emptied. Integrating the barrier must durably distinguish: barrier installed before the first journal, rollback completed with an authenticated recovery checkpoint, and committed handoff awaiting cleanup. Terminal work with a pending barrier must be included in reconciliation. Never treat an empty journal alone as proof of either rollback or commit; do not requeue or clear the barrier when the phase is ambiguous. Finalization callbacks run within the existing fence transaction and must not reacquire that same fence.


### Fenced journal recovery progress

Recovery can adopt a task barrier for the same work using a newer valid attempt, advance the task generation, and restore a nonempty journal under the write fence before clearing the barrier. A changed postimage refuses rollback and retains both journal and barrier for agent review. A pending barrier with an empty journal still requires agent reconciliation; the bounded executor now creates the barrier before a task-bound patch and finalizes it on handoff or fenced rollback; qualifying test receipts may be persisted without mapping them to task completion; missing or stale receipts remain explicit. Terminal handoff reconciliation and crash boundaries still require implementation and integration tests.


### Bounded task barrier integration

Task-bound bounded edits open a server-managed barrier under a writer fence before mutation. Successful handoff clears the journal and finalizes the barrier under a fence; cancellation or failed validation invalidates the task generation before rollback. A postimage conflict preserves the foreign change, journal and barrier and reports reconciliation required. Empty-journal recovery with a valid completed-rollback checkpoint can adopt and release the barrier; ambiguous empty journals remain for agent review. Terminal work with an open barrier is reported during startup reconciliation in successive bounded batches of 128 records. Eligible real broker receipts remain unmapped until the primary agent reviews them.


### Terminal handoff postimage recovery

A task-bound bounded handoff persists the final journal postimages in its terminal record. Startup reconciliation can adopt its pending barrier under a new fenced attempt and release it only after confirming every allowed file still matches the recorded postimage; a present journal must match the same manifest. A changed file, malformed manifest or inconsistent journal retains the barrier and requires agent review. Reconciliation and terminal journal cleanup each process at most 128 terminal records per pass and schedule the next batch when needed. A crash after barrier release but before terminal status update is reconciled only when the exact task finalization event, task generation, empty journal and fenced postimages agree; otherwise it requires manual review. Exact event lookup is time-bounded and independent of event position; timeouts remain visible and retryable. Broker receipts require primary-agent acceptance.

The broker records the evidence without mapping it to the task while a fenced work barrier is open. Every patch advances the task generation; only receipts from the current generation are included in the final handoff and earlier validation entries are marked stale. `recorded_unmapped` is evidence for review, not acceptance. Missing or partial evidence remains explicit. Primary-agent diff, test and integration review is still required before mapping or accepting a receipt. Current-source tests use an isolated application and synthetic work order; live model quality and RTX 5070 Ti measurements remain deferred.


### Bounded terminal cleanup safety

Terminal journal cleanup preserves journals when task barriers are unresolved or task identity is unavailable. It claims the work attempt fence, rechecks task and terminal state under that fence, and never erases a corrupt journal. Startup reconciliation and cleanup advance through stable keyset batches; unresolved leases remain retryable. An exact finalization-event lookup fails closed when the event is absent; a timeout leaves the status pending, reports its reason and schedules a retry.
