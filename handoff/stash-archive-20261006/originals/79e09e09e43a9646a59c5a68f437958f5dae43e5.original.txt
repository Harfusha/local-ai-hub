# T09 typed command receipt contract

## Classification

- Test criteria and test commands use `evidence_type="test"`.
- Benchmark criteria and benchmark commands use `evidence_type="benchmark"`.
- Lint, build, and other source checks use `evidence_type="source_review"`.
- `VerificationReceipt.create()` infers type from criterion and preserves `source_review` when a command ID exists. A lint command must not become a test receipt.
- A command-backed `source_review` receipt uses a `command_verification` artifact when `command_id` is present. A non-command source review continues to use a `source_review` artifact.

## Trusted command proof

Artifact tenant must equal receipt owner. JSON proof must bind all values below to receipt/task state:

```json
{
  "kind": "work_command_verification",
  "passed": true,
  "task_id": "<task id>",
  "owner": "<receipt owner>",
  "repository_revision": "<current revision>",
  "mutation_generation": 0,
  "criterion": "<configured criterion alias>",
  "command_id": "<broker command id>",
  "command_classification": "<test|benchmark|source_review>",
  "command": "<actual executed command>",
  "project_alias": "<resolved project alias>",
  "project_config_digest": "<current project config digest>",
  "project_environment_sha256": "<current effective environment digest>",
  "configured_command_sha256": "<resolved configured command digest>",
  "caller_arguments_sha256": "<permitted caller arguments digest>",
  "project_execution_binding_sha256": "<recomputed six-field binding>",
  "command_sha256": "<sha256 of exact executed command>",
  "exit_code": 0,
  "result": {"success": true, "exit_code": 0}
}
```

The receipt also carries matching `task_id`, `criterion`, `owner`, `repository_revision`, `mutation_generation`, `command_id`, and `evidence_id`. Completion checks the latest receipt per criterion, configured rule aliases, expected owner/revision/generation, receipt identity mapping, artifact tenant and proof fields, command success, and freshness. Missing or mismatched evidence rejects completion.

## T06 producer seam

For configured project receipts, the consumer requires and recomputes the v6 execution binding. It checks the resolved alias/config digest, the exact configured string or structured argv/root cwd, actual command text/hash and classification, the current effective environment hash, permitted caller arguments, and `project_execution_binding_sha256`. String commands permit no extra arguments. Structured argv arguments are parsed from the actual command, bounded, hashed, checked against the configured argv prefix, and rejected when they request help, collection-only, dry-run, shell operators, or invalid values. Environment values are hashed in memory and never written to receipt artifacts. Generic test/benchmark receipts without project config continue through the generic path and do not require project aliases.

`T06-T09-validation-receipts-v6-root-namespace-current.patch` has SHA-256 `2BC2AAED85A83126906D0F347C25BFD059FFF816B413093D09E3242804D22982`. `run_t09_t06_v6_real_broker_overlay.py` applied it only to a temporary copy of root `commands.py`, then ran the real broker with candidate T09 verifier/adapter. **1 passed in 10.90s**: configured structured pytest plus private env reference produced an accepted project receipt and completed the task; `--help` and generic broker execution did not mint a project receipt. Root and T06 worktrees were not changed by this overlay.

## Root project binding

Task project root comes from immutable task-creation event data and a physical `ScopeContext.repository_id`; managed `worktree_path` is accepted only when ownership metadata binds it to the same task, owner, worktree ID, branch and repository root. Mutable current checkpoint `repo_root` is ignored. Opaque repository IDs are not treated as paths. Payload root is accepted only when its resolved project root matches the trusted task root. Mismatch fails before receipt evaluation or checkpoint/completion writes. Direct task completion and terminal transition resolve the same trusted project settings and pass configured command definitions, current environment digest and config digest into receipt evaluation. The root-current terminal patch keeps T08 memory-audit validation and leaves T08 checkpoint handling and T16 terminal-transition implementation intact.

T21's test-only regression reported RED `2 failed, 1 passed` for foreign-root completion. Candidate adapter overlay later passed the same test `3 passed`; after receipt API grew config binding, the test overlay uses root current agent/task/project modules plus candidate adapter and drops only unsupported new verifier kwargs. Exact selectors and proof remain in the external T21 worktree; no T21 tests edited here.
